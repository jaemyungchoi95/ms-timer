# ms-timer

목표 시각까지 남은 시간을 1ms 단위로 표시하는 플립 시계.
기본은 퇴근 카운트다운이지만, 하루 일정(경유지 0~6개 + 최종)을 등록하면
시계는 항상 **다음 일정까지**를 센다 — 점심까지, 미팅까지, 그리고 퇴근까지.

시:분:초는 플립 카드가 착착 넘어가고, ms 3자리는 읽을 수 없는 속도로 흐른다.

## 실행

`dist/ms-timer.exe` — 설치 불필요.

## 조작

- **제목 클릭** — 헤더의 문구(뱃지+제목)를 누르면 일정 모달이 열린다.
  행 하나가 일정 하나다: `[뱃지] [HH:MM] [표시 문구] [도달 시 문구]`.
  - **경유지**는 우하단 시계+ 아이콘으로 추가하고(새 행은 맨 위) `✕` 로 지운다. 최대 6개.
    표시 문구는 그 구간 동안의 제목("점심까지"), 도달 문구는 그 시각의 팝업 문구다.
    비워두면 기본 문구("11:30까지" / "무언가 하실 시간입니다!")를 쓴다.
  - **FINISH 행**은 항상 하나 — 하루의 최종 시각이며 지울 수 없다.
    이 행의 표시/도달 문구가 곧 타이머 제목(진행/완료)이다. 예: "퇴근까지" / "퇴근".
  - **뱃지 클릭** — 아이콘 6종이 펼쳐진다. 행마다 다른 뱃지를 붙일 수 있고,
    현재 구간의 뱃지는 헤더와 알림 팝업에도 나타난다.
  - 우상단 저장 아이콘 = 전부 일괄 저장 후 닫힘, `X` 또는 **Esc** = 저장 없이 닫힘.
    시각은 저장할 때 자동 정렬된다. 경유지는 최종보다 일러야 하고 중복될 수 없다 —
    위반한 행은 테두리가 빨갛게 되고 저장이 비활성된다.
- **`T`** — 테마 전환 (다크 모던 ↔ 레트로 민트). 모달이 열려 있으면 동작하지 않는다.
- **`L`** — 언어 전환 (한국어 ↔ English). 기본 문구와 접근성 라벨에만 적용되고,
  직접 지은 문구는 건드리지 않는다. 첫 실행 언어는 OS 언어를 따른다.

일정(시각·문구·뱃지)·테마·언어는 다음 실행에도 기억된다. 기본값은 최종 18:00 이다.

경유지 시각에 도달하면 팝업(뱃지+도달 문구)이 뜨고 시계는 **그 즉시 다음 구간**으로
넘어간다 — 경유지에서 멈추는 일은 없다.

일정 시각에 도달하는 순간 알림 팝업이 뜨고 본 창이 화면 앞으로 올라온다.
팝업은 `확인` 클릭 또는 60초 뒤에 닫힌다. 이미 지난 시각으로 켜거나 과거
시각을 설정했을 때는 울리지 않는다 — 알림은 "방금 도달했다"는 사건이다.
Windows 정책상 키보드 포커스는 가져오지 않으므로 Esc 로는 닫히지 않는다.
알림 끄기는 없다 — 앱을 켜둔 채 두면 주말에도 매일 같은 시각에 울린다.
끄는 방법은 앱 종료뿐이다 (의도된 절제다).

최종 시각에 도달하면 `00:00:00.000` 에서 멈추고 완료 문구를 표시한다.
이미 지난 시각을 설정해도 마찬가지다 — 내일로 넘기지 않는다.
자정을 넘기면 경유지까지 포함해 다음 날 일정이 자동으로 재무장되므로 켜둔 채로 둬도 된다.

## 왜 ms 자리는 플립하지 않나

플립 애니메이션 1회는 최소 250ms가 필요하다. 그보다 짧으면 종이가 넘어가는 것으로
지각되지 않고 깜빡임이 된다. ms 자리는 1~100ms마다 바뀌므로 구조적으로 플립할 수 없다.

그래서 릴로 흐르게 했다. 모니터는 60Hz(16.7ms)이므로 오른쪽 릴은 초당 100바퀴를
돌지만 60번만 샘플링된다 — 읽을 수 없는 것이 정상이고 의도다.
"시간이 흐른다"(플립)와 "시간이 미친듯이 흐른다"(릴)를 한 화면에서 대비시키는 것이
이 앱의 전부다.

## 개발

프로젝트는 반드시 `/mnt/c` 아래에 둔다. WSL 파일시스템에 두면 Windows node가
`\\wsl$` UNC 경로로 접근하며 electron-builder가 실패한다.

```bash
node --test                              # 테스트 (WSL node)
cmd.exe /c "npm install"                 # 의존성 (Windows node 필수)
cmd.exe /c "npx electron ."              # 개발 실행
cmd.exe /c "npx electron-builder --win portable"   # exe 빌드 → dist/ms-timer.exe
```

`npm install`을 WSL node로 하면 linux용 electron 바이너리가 받아져 실행되지 않는다.

## 구조

```
src/lib/          순수 함수 — 로직 전부, 테스트 전부, DOM 모름
  countdown.js      시간 계산
  target-time.js    시각 파싱/포맷 — 범위 규칙은 여기에만 있다
  schedule.js       일정 — 경유지 파싱/구간 선택/checkpoint별 발화 tracker
  presets.js        프리셋 코어 (현재 UI 미배선 — 휴면)
  label.js          문구 정규화 — 12자 상한은 여기에만 있다
  strings.js        언어별 문자열 — ko/en 키 대칭을 테스트가 고정한다
  reel-phase.js     릴 위상 계산
  expiry-tracker.js 만료 에지 추적 — 전환/재무장 규칙은 여기에만 있다
src/renderer/     표현 계층 — 로직 없음, 테스트 없음
  flip-digit.js     카드 1장
  reel.js           릴 1개
  theme.js          테마 토글 (T)
  lang.js           언어 토글 (L) — aria/placeholder/html[lang]
  schedule-editor.js 일정 모달 — 행 편집·뱃지 picker + localStorage
  icons.js          뱃지 키 → 에셋 경로 (화이트리스트 사전)
  clock.js          조립 + rAF 루프 — 구간 선택·발화·제목/헤더 뱃지는 여기서만 쓴다
  popup.html/js/css 알림 팝업 — 문구·뱃지는 본창이 결정해 query 로 전달한다
  assets/icons/     뱃지 6종 + UI 크롬 3종 (Lucide)
src/preload.cjs   contextBridge — 렌더러→main 단방향 채널 (저장소 유일의 CJS)
src/main.js       BrowserWindow 생성 + 알림 오케스트레이션 (raise + 팝업 싱글턴)
```

시간 계산은 절대 시각 차분(`오늘 18시 - now`)이다. 누적 감산이 아니므로
드리프트가 없고 절전 복귀·NTP 보정·타임존 변경이 자동으로 반영된다.
경유지 발화는 표시와 분리된 checkpoint별 tracker 가 담당한다 — 표시 선택은
경유지가 지나는 프레임에 이미 다음 구간이라, 표시만 보면 만료 에지가 없다.

시각·일정 검증은 `parseTarget`/`parseWaypoints` 가 전담한다. 저장값과
사용자 입력이 같은 경로를 타므로 두 경로가 어긋날 수 없다.

그래픽이 통째로 바뀌어도 `src/lib/`는 손대지 않는다 — 이 경계가 요점이다.
